# Replica pack — audited adaptation

Source: [Jakeschincariol/replica-skill](https://github.com/Jakeschincariol/replica-skill) @77c9436 (MIT, see `LICENSE` in each skill directory), plugin version 1.0.0. Installed as 11 project skills: `replica-recon`, `replica-architect`, `replica-design`, `replica-build`, `replica-backend`, `replica-test`, `replica-diff`, `replica-entrepreneur`, `replica-brand`, `replica-launch`, `replica-deploy`.

## Review

- The repository was three days old with a single commit, so every file was read in full: 11 SKILL.md, 9 templates, 6 Python tools.
- Python tools (`sweep.py`, `contrast.py`, `parity.py`, `imgdiff.py`, `reviews.py`, `listing.py`) use only the standard library: no network, no subprocesses, and they write only the output file you pass them. All 57 upstream unit tests passed on the tools as installed. The PR review fixes below later changed `sweep.py` and `listing.py`; how those changes were checked is noted there.
- No hooks, no pre-approved tools, no prompt injection, no promotional instructions. The only content-scan hits (three invisible characters in `listing.py`: U+200D zero-width joiner, U+FE0F and U+FE0E variation selectors) are emoji-aware character counting. They are now written as `\u` escapes.
- The skills' own rules match this project's policy and were kept verbatim:
  - Clean room: functions and flows only, never the original's code, assets, copy, private APIs or network calls.
  - Public sources or the user's own account only. No scraping. Check terms that forbid building competitors.
  - No fake reviews or proof, and reviewers are not testimonials.
  - Trademark screening, a different palette and a sweep for leftovers before launch.
  - Nothing goes live without the user's go. The user buys, signs in and enters keys.

## Changes

1. Tool calls point to the project install (`python3 .claude/skills/replica-<x>/<tool>.py`, 19 occurrences in the SKILL.md files; the PR review fixes added one in `replica-design/tokens.json`); the note about `~/.claude/skills` paths in `replica-deploy` was replaced accordingly.
2. `replica-test`: added that `@playwright/test` is a new dev dependency (ask first) and that Chromium is pre-installed in Claude Code cloud sessions.

Not installed: plugin manifests and the upstream `tests/` folder.

## Notes for this project

- Review texts collected by `replica-entrepreneur` are research data. They stay local (`replica/reviews.csv`, `replica/feedback.md` and `replica/fixes.md`, whose lists quote reviews, are gitignored), personal data from reviews is not stored, and they are never used as marketing copy. Screenshots of the original (`replica/screens/`, `replica/diffs/`) stay local too. Since the PR review fixes, these rules are also in the skills, where the model sees them.
- External sources such as App Store feeds and the Hacker News API are blocked in cloud sessions until the owner allows them in the environment's network settings.

## Fixes from the PR review (2026-10-08)

- Descriptions (all 11 SKILL.md): each now opens with "Replica pack, step N of 11: a clean-room rebuild of an existing app. Only when the owner is explicitly building such a clone (replica/recon.md exists); not for ordinary work on this CRM" (recon: "Only when the owner explicitly asks to clone or rebuild an existing app"). Generic trigger phrases were removed, for example "add login", "send emails", "deploy it", "ship it", "find bugs", "does it work", "is it ready", "how does X work", "landing page", "pricing" and "name my app". Clone-specific ones stay ("clone this app", "test my clone", "after /replica-..."). Why: in this CRM repo those everyday requests could load a Replica skill and steer the session to the clone stack (Supabase, Stripe, Vercel). `disable-model-invocation` was not added, because that needs the owner's OK.
- Guard line (all 11 SKILL.md): each body now starts with "**Only for a Replica project the owner asked for** (a clone of an existing app, with `replica/recon.md`), not for ordinary work on this CRM." `replica-recon` and `replica-architect` leave out the recon.md part: recon writes it, and architect already stops without it. Why: a second check after a wrong match.
- `replica-brand/sweep.py`: now also skips `.claude/` and `CLAUDE.md` files, virtualenvs (any folder with a `pyvenv.cfg`, and `.venv-scrapling`), tool folders (`.playwright-cli`, `.auth`, `.scrapling_cache`, `.unlazy`, `.pgdata`, Python tool caches), and `research_notes/`, `reports/`, `crawl_data/` and `dev_cache/` at the top level only, so `src/reports/` is still searched. `.github/` is still searched, because workflows ship. Files that can hold secrets (`.env`, `.env.*`, `*.env`, `.npmrc`, key and credential files, Playwright auth state) are still searched, but a hit there shows only file and line, never the text. Exit codes are unchanged (0 clean, 1 hits, 2 usage error). Why: run from this repo's root, the sweep flagged the pack's own examples and the awesome-design brand files (Calendly 8 hits, Stripe 99, Linear 65, all under `.claude/`), so the required clean sweep could not pass without editing the owner's skills, and it printed `.env` lines with their secrets. Checked: `py_compile`; the five upstream `sweep.py` test cases, rewritten as a local test, still pass; new cases cover every skip and the hidden lines; on a copy of this repo the sweep is clean for Calendly, Notion, Stripe, Linear, Airbnb and Vercel, and a planted `.env` secret no longer appears.
- `replica-brand/SKILL.md` step 6: says what the sweep skips, that lines in `.env` and key files are not shown, and that Claude does not print them either: it fixes `.env.example` itself and tells the owner the file and line for the others.
- `replica-deploy/SKILL.md` preflight: `npx playwright test` became `npx --no-install playwright test`, which fails instead of downloading when Playwright is missing. Only the count and file:line of sweep hits go into `deploy.md`. Why: without a local Playwright, a bare npx call downloads and runs the latest `playwright` without asking, and `deploy.md` is not gitignored.
- `replica-test/SKILL.md` step 2: `@playwright/test` and `@axe-core/playwright` are both named as new dev dependencies (ask the owner first, `--save-exact` with exact versions: `@playwright/test@1.63.0` and `@axe-core/playwright@4.13.0`, checked on npm on 2026-10-17). `playwright install` and `playwright test` run with `npx --no-install`. In cloud sessions the version is pinned to the pre-installed Playwright, so its Chromium matches. A `playwright.config.ts` with `testDir: 'e2e'` is written. Why: every spec needs axe, but only `@playwright/test` was behind the ask-first note.
- `replica-test/e2e.example.spec.ts` was renamed to `e2e.example.ts` (new file, old one deleted). The content is unchanged apart from one comment line that says why. Why: Playwright's default test match (`**/*.@(spec|test).?(c|m)[jt]s?(x)`) collected it from `.claude/` and aborted the whole run on the missing `@axe-core/playwright`. Checked with the pre-installed Playwright 1.56.1 (`playwright test --list`): the old name aborts with 0 tests, the new name lists only `e2e/`. `tsc` still leaves it out (dot folder).
- `replica-launch/listing.py`: the three invisible literal characters are now written as `\u200d`, `\ufe0f` and `\ufe0e`, so the file is plain ASCII. Behaviour is unchanged: bytecode, names and constants are identical, and `length()`, `lint()`, `render()` and `main()` give the same results as before on 748 test strings and the example listing.
- Privacy (`replica-entrepreneur`, `replica-recon`, `replica-diff`): the rule from "Notes for this project" is now in the skills. Review texts and screenshots of the original stay local and are never committed, pushed or published, and no personal data from reviews is stored. `replica-diff` now writes its overview diff image to `replica/diffs/S07.png` instead of `diff-S07.png` in the repo root. `replica/fixes.md` quotes reviews in its three lists, so `.gitignore` now covers it too. Why: the rule lived only in this file, which no skill links to.
- Approval gates (`replica-deploy`, `replica-launch`): `eas build` and `eas submit`, store uploads, review submissions and any purchase with a real payment method (the live-mode test purchase too) need the owner's explicit OK, and the owner makes those purchases. `eas-cli` is named as a new tool (ask first, pin the version). The deploy checklist says the real purchase is made by the owner. Launch posts, community replies and messages to the first users are drafts that the owner sends. Why: the general "nothing goes live without the user's go" did not clearly cover these steps.
- `replica-design/tokens.json`: the `_about` note now gives the project path, `python3 .claude/skills/replica-design/contrast.py replica/design/tokens.json`. The old `python3 contrast.py tokens.json` failed from the repo root.
- `replica-entrepreneur`: step 2 copies `themes.json` to `replica/themes.json` once and passes `--themes replica/themes.json`, and the `_about` note in `themes.json` says the same. Why: "edit it for the app's category" made each project edit the tracked skill file. `reviews.py` and `contrast.py` do not read the `_about` notes, so the tools behave as before.
- Recorded here, fixed earlier: the six `__pycache__/*.cpython-311.pyc` files that came with the pack were removed, and `__pycache__/` and `*.pyc` are gitignored (commit 8054267).
